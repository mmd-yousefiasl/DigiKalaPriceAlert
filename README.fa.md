> یک پلتفرم کامل رصد قیمت برای دیجی‌کالا — با هشدار لحظه‌ای در تلگرام و پیامک، یکپارچه‌سازی با Marketplace API دیجی‌کالا و معماری Clean Architecture روی .NET 10.

<h2 align="center" dir="rtl">معرفی</h2>

«دیجی‌کالا پرایس الرت» یک پلتفرم کامل رصد قیمت برای [دیجی‌کالا](https://www.digikala.com) — بزرگ‌ترین فروشگاه اینترنتی ایران — است. کاربر آدرس یک محصول را وارد می‌کند، فروشنده‌ها و رنگ‌های موردنظرش را انتخاب می‌کند و به‌محض هر حرکت بازار خبردار می‌شود: تغییر قیمت، ورود و خروج فروشنده‌ها از موجودی، و جابه‌جایی برنده باکس (<span dir="ltr">Buy Box</span>). هشدارها از طریق ربات تلگرام و پیامک الگویی ارسال می‌شوند و تاریخچه کامل تغییرات هم در سایت قابل مشاهده است.

در کنار بخش ردیابی، پلتفرم با **Marketplace API دیجی‌کالا** هم کار می‌کند و از طرف فروشنده‌ها تنوع‌ها، موجودی و قیمت‌ها را مدیریت می‌کند. یک لایه تجاری کامل هم روی این هسته سوار است: ورود با کد پیامکی، پلن‌های اشتراک، پرداخت آنلاین، محاسبه‌گر سود فروشندگان و پنل مدیریت کامل با امکانات CMS.

<h2 align="center" dir="rtl">چگونه کار می‌کند</h2>

قلب سیستم، یک پایپ‌لاین رصد رویدادمحور است:

</div>

```
PriceMonitorWorker  (BackgroundService · every 15 minutes)
        │
        ▼
Load tracked products ─── only products watched by at least one user
        │
        ▼
Scrape DigiKala API ──── sequential · random 0.8–1.5s delay
        │                 early abort when rate-limited
        ▼
Reconcile scraped market vs database
        │   price change · stock out / back in stock
        │   buy box won / lost · title & image updates
        ▼
Persist per product ──── failure isolation: one bad product
        │                 never poisons the rest of the batch
        ▼
Publish ProductVariantMarketStatusUpdatedEvent (MediatR)
        │                 one event per affected color group
        ▼
MarketAlertService
        ├──► Telegram bot — one rich message per watcher,
        │    with a deep link to their own product page
        ├──► SMS — bounded in-process queue → SmsIr worker
        └──► Site — tracking rows flagged unread in the user panel
```

<div dir="rtl" align="right">

**چه چیزی این پایپ‌لاین را محتاط و دقیق می‌کند:**

- **جزئیات تا سطح هر فروشنده و هر رنگ** — تنوع‌ها به ردیف‌های فروشنده تبدیل می‌شوند (`ProductVariantSeller`)؛ بنابراین سیستم **هر** فروشنده از **هر** تنوع رنگی را رصد می‌کند: قیمت، امتیاز، فعالیت و وضعیت باکس — نه فقط یک قیمت برای کل محصول.
- **مقاومت در برابر محدودیت نرخ** — درخواست‌ها با تأخیر تصادفی از هم فاصله می‌گیرند و به‌محض مشاهده سیگنال `RateLimited` کل چرخه زودتر متوقف می‌شود، به‌جای آنکه به API فشار بیاورد.
- **گروه رنگی، واحدِ تغییر است** — شناسه تنوع در دیجی‌کالا برای هر ترکیب رنگ × فروشنده یکتاست؛ در نتیجه تغییرها برای هر گروه رنگی به یک رکورد تغییر و یک موج هشدار تجمیع می‌شوند.

<h2 align="center" dir="rtl">امکانات</h2>

**برای خریداران و ردیاب‌ها**

- **ردیابی هر محصول با آدرس** — چسباندن لینک دیجی‌کالا (یا شناسه محصول)، پیش‌نمایش در مودال جست‌وجو و انتخاب موارد موردنظر برای رصد
- **ردیابی باکس** — دانستن برنده و بازنده باکس هنگام تغییر قیمت فروشنده‌ها، از طریق `IBuyBoxStrategy` قابل‌تعویض
- **هشدارهای تلگرام** — گزارش‌های غنی از تغییرها همراه با لینک مستقیم به صفحه ردیابی خودِ کاربر
- **هشدارهای پیامکی** — پیامک الگویی با SmsIr، ارسال‌شده توسط ورکر مصرف‌کننده صف اختصاصی
- **صندوق خوانده‌نشده در سایت** — هر تغییر، ردیف‌های ردیابی مربوطه را خوانده‌نشده علامت می‌زند تا چیزی از چشم کاربر دور نماند

**برای فروشندگان — Marketplace API دیجی‌کالا**

- **کاتالوگ و تنوع‌های فروشنده** — فهرست‌کردن محصولات و تنوع‌های فروشنده مستقیماً از طریق API مارکت‌پلیس
- **مدیریت موجودی و قیمت** — خواندن و به‌روزرسانی موجودی و قیمت فروشِ تنوع‌ها، شامل به‌روزرسانی گروهی
- **هوش قیمت‌گذاری** — قیمت برنده، حدود قیمت و پروموشن‌های فعال هر تنوع
- **تأیید سفارش با پلن‌های قیمت‌گذاری خودکار** — فرایند سفارش، پلن‌های قیمت‌گذاری خودکار را می‌شناسد

**پلتفرم**

- **ورود با کد پیامکی (OTP)** — ورود با شماره موبایل، کد تأیید و جریان ارسال مجدد
- **اشتراک و پرداخت** — پلن‌های اشتراک با امکانات و مدت‌زمان، سفارش‌ها و پرداخت آنلاین با جریان <span dir="ltr">request/verify</span> درگاه
- **پنل مدیریت کامل** — کاربران، نقش‌ها و دسترسی‌ها، سفارش‌ها، پرداخت‌ها، پنل پیامک، تراکنش‌های کیف پول و بیشتر
- **CMS داخلی** — وبلاگ با دسته‌بندی، سوالات متداول، تیکت با پیوست، خبرنامه، اطلاع‌رسانی سایت، سایت‌مپ و شبکه‌های اجتماعی
- **محاسبه‌گر سود** — ابزار عمومی و رایگان برای برآورد سود خالص فروشنده (کمیسیون، مالیات بر ارزش افزوده، هزینه ارسال و مرجوعی)
- **قابلیت مشاهده عملیات** — لاگ Serilog با ارسال رویدادهای `Error`/`Fatal` به‌صورت دسته‌ای به یک کانال خصوصی تلگرام

<h2 align="center" dir="rtl">معماری</h2>

راه‌حل بر پایه **Clean Architecture** و در چهار پروژه با مسئولیت مشخص سازمان‌دهی شده است:

</div>

```
DigiKalaPriceAlert.slnx
├── Domain        # موجودیت‌ها، enumها، رویدادهای دامنه و هسته مشترک — سی‌شارپ خالص
├── Application   # سرویس‌ها و اینترفیس‌ها، DTOها، هندلرهای MediatR، ابزارها
├── Data          # DbContext مبتنی بر EF Core — PostgreSQL با Npgsql
└── Web           # میزبان ASP.NET Core MVC: سایت، Areaها و سرویس‌های پس‌زمینه
```

<div dir="rtl" align="right">

| لایه | مسئولیت |
|------|---------|
| **Domain** | موجودیت‌ها (`Product`، `ProductVariantSeller`، سفارش‌ها، پلن‌های اشتراک، کاربران)، enumها و رویدادهای دامنه مانند `ProductVariantMarketStatusUpdatedEvent` — به‌همراه هسته مشترک (`Result`، تعریف خطاها، ابزارهای سایت). بدون وابستگی به EF Core یا ASP.NET. |
| **Application** | بیش از ۳۵ سرویس کاربردی پشت اینترفیس‌ها، DTOها، هندلرهای MediatR (هشدار بازار، اطلاع‌رسانی‌ها، ابطال کش)، ابزارها و ویژگی‌های اعتبارسنجی. |
| **Data** | `DbContext` با ارائه‌دهنده Npgsql، استراتژی اجرای تلاش مجدد و پیکربندی موجودیت‌ها. |
| **Web** | سایت عمومی + دو Area با نام `Admin` و `UserPanel` (ویوهای Razor)، سه سرویس پس‌زمینه، HTTP Clientهای typed، پایپ‌لاین Serilog، فشرده‌سازی پاسخ و باندلینگ. |

**الگوهای قابل توجه**

- **الگوی Result** — سرویس‌ها `Result` / `Result<T>` با خطاهای typed برمی‌گردانند (مثل `DigiKalaErrors.RateLimited`)؛ exception ابزار جریان کنترل نیست
- **هشداردهی رویدادمحور** — reconciler اول ذخیره می‌کند، بعد منتشر می‌کند؛ هندلرهایی مانند `MarketStatusAlertHandler` اطلاع‌رسانی را انجام می‌دهند
- **الگوی Strategy** — `IBuyBoxStrategy` برنده باکس هر گروه رنگی را تعیین می‌کند (`HighestRankBuyBoxStrategy`)
- **صف‌های محدود درون‌پردازشی** — پیامک‌ها و به‌روزرسانی‌های تلگرام از کانال‌های bounded عبور می‌کنند و ورکرها آن‌ها را مصرف می‌کنند؛ در نتیجه موج‌های ناگهانی جذب می‌شوند، نه دور ریخته
- **HTTP Clientهای typed** — کلاینت API دیجی‌کالا با هدرهای سفارشی، decompress از نوع gzip/brotli و تایم‌اوت ۱۵ ثانیه به‌صورت متمرکز در DI ثبت می‌شود

<h2 align="center" dir="rtl">سرویس‌های پس‌زمینه</h2>

| ورکر | ریتم | مسئولیت |
|------|------|---------|
| `PriceMonitorWorker` | هر ۱۵ دقیقه | رصد و تجدیدنظر همه محصولات ردیابی‌شده و انتشار رویدادهای تغییر |
| `TelegramUpdateWorker` | پیوسته | مصرف به‌روزرسانی‌های تلگرام از صف و پردازش هرکدام در scope مجزا |
| `SmsConsumerWorker` | پیوسته | مصرف آیتم‌های پیامک از صف و ارسال پیام‌های الگویی با SmsIr |

<h2 align="center" dir="rtl">تصمیم‌های فنی کلیدی</h2>

**رصد محتاط و مقاوم به محدودیت نرخ.** API عمومی دیجی‌کالا یک API رسماً باز نیست. ورکر به‌صورت ترتیبی و با تأخیر تصادفی ۰٫۸ تا ۱٫۵ ثانیه بین محصولات رصد می‌کند و به‌محض سیگنال محدودیت نرخ، کل چرخه زودتر متوقف می‌شود — احتیاط داخل خودِ حلقه ساخته شده است، نه اینکه بعداً به آن چسبانده شود.

**ایزوله‌سازی خطا در سطح هر محصول.** ذخیره‌سازی ناموفق (تضاد قید، داده خراب) فقط تغییرات در انتظارِ همان محصول را برمی‌گرداند و بقیه کار ادامه پیدا می‌کند — یک محصول خراب هرگز نمی‌تواند بقیه دسته یا تلاش بعدی را از کار بیندازد.

**اول ذخیره، بعد انتشار.** رویدادهای تغییر فقط پس از commit شدن وضعیت دیتابیس به MediatR می‌رسند؛ بنابراین هیچ هشداری به داده‌ای ارجاع نمی‌دهد که واقعاً وجود ندارد.

**فروشنده‌های غیرفعال نامرئی نمی‌شوند.** فروشنده‌های بدون موجودی (soft-delete شده) به رصد ادامه می‌دهند تا بعداً بتوانند دوباره فعال شوند؛ تطبیق بر اساس کلید (محصول، تنوع، فروشنده) انجام می‌شود، بنابراین فروشنده بازگشتی ردیف خودش را احیا می‌کند، نه اینکه ردیف تکراری بسازد.

**Sink خطایی که هرگز crash نمی‌کند.** رویدادهای `Error`/`Fatal` Serilog از یک کانال bounded عبور می‌کنند و به‌صورت دسته‌ای به کانال خصوصی تلگرام می‌روند — همیشه زیر سقف ۴۰۹۶ کاراکتر تلگرام می‌مانند و خطای داخل خود Sink هرگز نمی‌تواند خطای دیگری بسازد.

**پیش‌نیازها**

- &#x200E;.NET 10 SDK
- PostgreSQL
- ابزار `dotnet-ef` (manifest ابزارها در `Web/dotnet-tools.json` موجود است)

**اجرای پروژه**

</div>

```
git clone https://github.com/mmd-yousefiasl/DigiKalaPriceAlert.git
cd DigiKalaPriceAlert
dotnet tool restore
dotnet restore
dotnet ef database update --project Data --startup-project Web
dotnet run --project Web
```
